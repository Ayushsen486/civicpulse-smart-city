# CivicPulse — Permanent Development Rules

> These rules apply to **every** agent, contributor, and CI pipeline working on
> this repository. Violations must be caught in code review.

---

## 1. Repository Layout

```
smartcity/
├── civicpulse-app/          # Flutter mobile app
├── civicpulse-backend/       # Spring Boot REST API
├── civicpulse-admin/         # React + TypeScript admin dashboard
├── civicpulse-db/            # Flyway migrations & seed data
├── infrastructure/           # Docker, docker-compose, nginx, scripts
├── docs/                     # Architecture, API, ERD, runbooks
├── .github/                  # CI/CD workflows
└── AGENTS.md                 # This file (do NOT move or rename)
```

Each sub-project is self-contained with its own build file and README.

## 2. Language & Framework Rules

### 2.1 Flutter / Dart (`civicpulse-app/`)
- **State management**: Riverpod (riverpod + flutter_riverpod + riverpod_annotation). No other state management library.
- **Navigation**: go_router.
- **HTTP**: dio with interceptors for JWT refresh.
- **Architecture**: Feature-first folder structure with clean separation (presentation → application → domain → data).
- **Null safety**: Always enabled; no `// ignore: null` pragmas.
- **Linting**: Use `flutter_lints` or stricter. Zero warnings in CI.
- **Tests**: Every new feature must include at least widget tests. Integration tests for critical flows.

### 2.2 Java / Spring Boot (`civicpulse-backend/`)
- **Java version**: 21 (LTS).
- **Build tool**: Gradle (Kotlin DSL).
- **Architecture**: Controller → Service → Repository. No business logic in controllers.
- **Validation**: Use `jakarta.validation` annotations on DTOs. Never trust client input.
- **Error handling**: Global `@ControllerAdvice` with RFC 7807 Problem Detail responses.
- **Logging**: SLF4J + Logback. Structured JSON in production.
- **Database access**: Spring Data JPA + Hibernate Spatial for PostGIS.
- **Migrations**: Flyway only. Never use `ddl-auto=update` in any profile.
- **Security**: Spring Security 6 + JWT (access + refresh tokens). Method-level `@PreAuthorize`.
- **Tests**: JUnit 5 + Mockito for unit; @SpringBootTest + Testcontainers for integration.
- **API versioning**: URI prefix `/api/v1/`.

### 2.3 React / TypeScript (`civicpulse-admin/`)
- **Build tool**: Vite.
- **State management**: Zustand or TanStack Query for server state.
- **Component library**: shadcn/ui + Tailwind CSS (admin dashboard exception to vanilla CSS rule).
- **Routing**: React Router v6.
- **Forms**: React Hook Form + Zod validation.
- **HTTP**: Axios with interceptors matching the Flutter pattern.
- **Tests**: Vitest + React Testing Library.

### 2.4 Database (`civicpulse-db/`)
- **Engine**: PostgreSQL 16 + PostGIS 3.4.
- **Migrations**: Flyway with versioned SQL files (`V001__description.sql`).
- **Naming**: `snake_case` for tables and columns. Plural table names (`issues`, `users`).
- **Soft deletes**: Use `deleted_at TIMESTAMPTZ` where business requires audit trail.
- **Timestamps**: Every table must have `created_at` and `updated_at` (TIMESTAMPTZ, UTC).
- **UUIDs**: Primary keys are `UUID` (generated by the database via `gen_random_uuid()`).
- **Indexes**: Every foreign key must be indexed. Spatial columns use GiST indexes.

## 3. Security Rules

- **Secrets**: Never commit secrets. Use environment variables or Docker secrets.
- **Passwords**: bcrypt with cost factor ≥ 12.
- **JWT**: Access token TTL = 15 min. Refresh token TTL = 7 days. Rotate refresh tokens.
- **CORS**: Explicit allow-list of origins. No wildcards in production.
- **Rate limiting**: All public endpoints must be rate-limited.
- **Input sanitization**: All user-supplied text is sanitized before storage.
- **File uploads**: Validate MIME type, enforce size limits, store outside webroot.

## 4. API Design Rules

- RESTful conventions: plural nouns, HTTP verbs for actions.
- Consistent envelope: `{ "data": ..., "meta": ..., "errors": [...] }`.
- Pagination: cursor-based for feeds, offset-based for admin tables.
- Filtering: query parameters (e.g., `?status=OPEN&priority=HIGH`).
- All dates in ISO 8601 UTC.
- File uploads via `multipart/form-data`; everything else via `application/json`.

## 5. Git & CI Rules

- **Branching**: `main` (production) → `develop` → `feature/*`, `fix/*`, `chore/*`.
- **Commits**: Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`).
- **PR rules**: At least 1 approval. All CI checks green. No force-push to `main` or `develop`.
- **CI pipeline**: lint → test → build → (on main) deploy.

## 6. Documentation Rules

- Every public API endpoint must be documented in OpenAPI 3.1.
- Every database migration must have a corresponding entry in `docs/migrations.md`.
- Architecture Decision Records (ADRs) live in `docs/adr/`.
- README in every sub-project root.

## 7. Docker & Deployment Rules

- All services must run via `docker-compose up` for local development.
- Production images must be multi-stage builds with minimal base images.
- Health checks on every container.
- No `latest` tags in production; always pin versions.

## 8. Performance Rules

- Backend response time target: p95 < 200ms for reads, < 500ms for writes.
- Mobile app cold start target: < 3 seconds.
- Database queries must not do full table scans on tables > 10k rows.
- Images must be compressed/resized before storage.

## 9. Accessibility & i18n

- Mobile app must support English and Hindi (at minimum).
- Admin dashboard must meet WCAG 2.1 AA.
- All user-facing strings must be externalized (ARB files for Flutter, i18n JSON for React).
